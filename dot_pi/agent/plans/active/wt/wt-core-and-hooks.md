# Workspace brick rebuild — full roadmap (herdr × wt × container × pi)

## Goal

One ordered plan for the **entire workflow**, not just wt: herdr (surface) + wt (durable lifecycle) + `container-sandbox` (VM routing) + the pi `workspace` orchestration skill + pi-subagents wiring + glue. End state: a smooth daily loop — spawn or `/workspace` → container-provisioned worktree → herdr pane (or headless mission) running isolated pi sessions cleanly.
- Each phase is independently testable; nothing depends backward; every phase ends in its own validation gate.
- The system map (`~/Development/tools/system-map`) stays the single source of truth: any contract change discovered lands in `src/*.d2` → `build.sh` as part of that phase.

## Context

- **Verified Sep 10:** repos re-homed (`nextnode/fitapp` on `main`, `clients/accor/product-data-apps` on `develop` — spawn bases the current checkout position, not defaults); herdr 0.9.0 has native `worktree create/list/open/remove` + `agent start` (surface overlap → Q1); Apple container CLI 1.3.1 with `node:24` and `studio-dev:node24-pnpm11` cached; pi-subagents installed (the ephemeral family already exists: `worktree:true`, `baseRef`, handoff manifests, confirm-required `worktree.discard`); d2 0.9 · map builds green; `wt` repo scaffolded at `~/Development/tools/wt` (fresh).
- **Locked decisions carried into every phase:**
  - Base = **current HEAD** of the source checkout; `--base <ref>` override; never a discovered default branch, never hardcoded `main/master`; detached HEAD fine.
  - Dirty source **never blocks** — one informational note; `--carry` = `git stash push -u` (source) → `git stash apply` (new worktree) → drop. Move, not copy.
  - Hard errors over silent divergence: branch exists / already checked out / ambiguous repo arg. **Amended 2026-09-15 (phase 6):** an existing branch is no longer simply refused — `wt spawn <branch>` adopts it (and tracks a remote-tracking ref), while a branch checked out anywhere, an ambiguous remote name and a `--base` combined with an existing branch stay hard errors.
  - Container naming `wt-<project-slug>-<hash8>`; teardown stop+rm by **exact** name (no prefix collisions).
  - Two worktree families never share a base dir; wt hooks never touch pi-managed worktrees; one writer per worktree; handoff durable before any discard.
  - `wt` = PATH binary (POSIX sh, jq, git, container CLI; herdr CLI optional at launch time) — pi's bash tool cannot see zsh autoloads.
  - Activation mirror: init hooks key on exactly what the extension keys on — `.containerize` marker or `activation: "always"`; no half-states.
  - Ownership: **herdr = surface, wt = lifecycle, pi extensions = session-level, pi-subagents = ephemeral lanes**; the only pi → wt edge is `wt --json` through thin tools (delegate, never re-implement).
  - Per-project container pinning via `<repo>/.pi/container.json` (image/env/cpus); global knobs `~/.config/wt/config.json`; registry `~/.local/state/wt/registry.json` = owner/writer/attachment source of truth.

  recorded branch, by the branch the checkout holds, or the current checkout; `--restore` = `git switch <recorded>` with
  a post-check and a distinct message when the recorded branch no longer exists; `--adopt` = re-record `branch`/`base`

  attachment is a note, not a blocker. A healthy workspace is a no-op. Payload:
  `{ok, workspace, repair{path,action,branch,previous,held}}` (action `restored`/`adopted`/`none`), `repair_refused` added
  to the error namespace and the jq contract.
- Read-only truth split, no new global state: `wt_checkout_live_branch` (`lib/checkout.sh`) answers what a checkout
  actually holds, `wt_row_for_path` (`lib/registry.sh`) reads one row straight from the file so hints never take the lock
  or fail on a broken registry, and every dead end now names its fix: `spawn` distinguishes a drifted holder
  (`wt repair --restore|--adopt <path>`) from a normal holder (`wt switch <branch>`); `switch` on a miss explains the
  holder (naming the recorded branch and both repair modes) or prints `wt spawn <repo> <branch>`; `switch` on a
  `branch_changed` row names both repair modes.
