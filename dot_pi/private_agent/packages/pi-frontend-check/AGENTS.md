# Frontend Check

Read `README.md` before changing browser behavior; it defines the local Brave contract and verification commands.

`extensions/browser.ts` owns session operations; `browser-connection.ts` owns the client connection and its tabs, with shared or isolated lifecycle according to `CDP_URL`; `browser-launch.ts` owns how every isolated browser and context is launched (flags, launch and context options); `profile-store.ts` owns per-session profile directories and how one is maintained (cache pruning, live-lock guard); `state-maintenance.ts` owns the retention window and the load-time sweep of profiles, captures and specimens. `extensions/scenario.ts` owns scripted, parallel scenario runs in isolated contexts; `extensions/scenario-state.ts` owns checkpoint state, the action and scenario `probe` before/after it. `config-schema.ts` owns config shapes; `schema.ts` owns defaults and tool schemas; `config.ts` validates config. Playwright types stay inside browser adapter modules. `tools.ts` and `index.ts` adapt the public Pi API. Pi and the local house `renderers/` own presentation; do not add the old compact-tools bridge.

Keep code and persistent instructions in English. Load the `coding` and `harness-tuning` skills before modifying extension code or instructions. Run package checks from this directory; format only changed code files. Real-browser tests are opt-in and use installed Brave, never an automatic browser download.
